## 1. 项目概述

rsmb-rs 是一个命令行工具，为已有视频**后期添加**自然的动态模糊（Motion Blur），效果对标 After Effects 的 ReelSmart Motion Blur（RSMB）插件。

真实相机拍摄时，快门在曝光期间会记录下物体的运动轨迹，形成模糊。游戏录屏、CG 渲染等素材是逐帧清晰的，缺乏这种模糊，快速运动的画面会显得"卡顿感"或"频闪"。rsmb-rs 通过**光流法**估计相邻帧之间每个像素的运动向量，再沿运动轨迹做定向采样叠加，模拟相机快门曝光过程，从而让运动画面呈现电影般的顺滑模糊。

**核心特性**

- 读取常见视频格式（MP4 / MKV / MOV 等，依赖 ffmpeg 解码）
- 金字塔 Lucas-Kanade 稠密光流，逐像素运动向量场
- **GPU 加速**（`--gpu`）：光流与模糊合成全部在 GPU compute shader 上执行，兼容 NVIDIA / AMD / Intel 核显（Vulkan / DX12 / Metal 后端）
- 快门角度（shutter angle）控制模糊量，语义与 RSMB / 电影相机一致
- 以当前帧为曝光中心的对称采样，避免画面"漂移"
- 三线程流水线（解码 / 处理 / 编码）+ 帧缓冲池回收
- 输出 H.264 MP4，自动携带原视频音轨；VFR 源按 avg_frame_rate 处理保持音画同步

## 2. 总体架构

```
输入视频 (MP4)
     │
     ▼
┌──────────────────┐  解码线程：ffmpeg → RGB24 rawvideo 管道
│  video::Decoder  │  （帧缓冲池回收，零拷贝复用）
└──────────────────┘
     │ 三帧滑动窗口 (prev / cur / next) + 灰度缓存轮转（每帧仅转换一次）
     ▼
┌──────────────────┐   CPU 路径：rayon 并行金字塔 LK
│  光流 + 模糊      │   GPU 路径：WGSL compute shader 全管线
│  (flow / blur /  │   前向流 cur→next + 后向流 cur→prev
│   gpu 模块)      │   中值滤波去噪 → 沿轨迹快门采样合成
└──────────────────┘
     │ 处理后 RGB 帧
     ▼
┌──────────────────┐  编码线程：libx264 + 音轨复制（AAC）
│  video::Encoder  │  +faststart
└──────────────────┘
     │
     ▼
输出视频 (MP4)
```

**设计决策**

| 决策 | 理由 |
| --- | --- |
| ffmpeg 外部进程解码/编码 | 避免绑定庞大的 FFmpeg C API；支持所有 ffmpeg 能读的格式 |
| wgpu 而非 CUDA/OpenCL | 跨 vendor（NVIDIA/AMD/Intel 核显通吃），纯 Rust 安全 API |
| 自研光流而非调 OpenCV | 零重型依赖；CPU/GPU 两套实现共享同一算法语义 |
| Lucas-Kanade + 金字塔 | 经典、稳定、易并行；金字塔解决大位移问题 |
| GPU 上数据全程驻留显存 | 回读是 PCIe 上最贵的操作；每帧只回读最终 RGB 一次 |
| 当前帧中心对称曝光 | 与 RSMB 默认行为一致，模糊不偏移主体位置 |
| 逐帧流式管道 | 内存只持有 3 帧 + 光流场，可处理任意时长视频 |

## 3. 核心算法

### 3.1 光流估计（`flow.rs` / GPU 同款）

**目标**：对当前帧 A 的每个像素 (x, y)，求运动向量 (u, v)，使其在帧 B 中对应 (x+u, y+v)。

**(1) 高斯金字塔**
两帧分别构建金字塔（5-tap 高斯核 `[1,4,6,4,1]/16` 模糊 + 2 倍降采样），层数自适应（最粗层最小边 ≥ 24 px，最多 6 层，`--levels` 可固定）。大位移在粗层变小，LK 的线性化假设才成立。

**(2) Lucas-Kanade 求解**
假设窗口内像素运动一致，对每个像素建立最小二乘系统：

```
[ ΣIx²   ΣIxIy ] [u]   [ΣIxIt]
[ ΣIxIy  ΣIy²  ] [v] = [ΣIyIt]
```

- `Ix, Iy`：参考帧空间梯度（中心差分）
- `It`：时间梯度，即 B 按当前流估计 warp 后与 A 的差
- `Σ`：窗口内求和（默认半径 7；CPU 用前缀和 O(1)，GPU 用每线程窗口循环）
- 2×2 系统解析求解，加 Tikhonov 正则（对角 +1e-3）保证平坦区稳定；单步更新钳制在 ±5 px 防发散

**(3) 由粗到精 + 迭代**
最粗层从零向量开始求解；每上升一层，流场双线性上采样并 ×2 作为初值，再迭代求解（默认每层 5 次）。

**(4) 中值滤波**
对 u、v 分量各做 3×3 中值滤波，去除光流野值，同时较好保留运动边界。
（GPU 实现：9 元素 4 趟冒泡——第 4 趟结束后 index 4 恰为中位数。）

**验证**：合成方块（每帧平移 +10, +6 px）测试，方块区域平均前向流估计为 (9.51, 6.51)，误差 < 0.5 px。

### 3.2 动态模糊合成（`blur.rs` / GPU `motion_blur_px`）

**(1) 快门角度 → 曝光长度**

```
span = shutter_deg / 360 × 0.5
```

曝光以当前帧时刻为中心：360° 快门 = 曝光覆盖完整帧间隔（前后各半帧运动）；180° = 前后各 1/4 帧运动。与电影相机及 RSMB 的 shutter angle 语义一致。

**(2) 轨迹采样**
对每个像素，在其运动轨迹上均匀取 N 个采样点（参数 t ∈ [-1, 1]）：

```
t < 0：采样位置 = p + t × span × flow_bwd(p)   （曝光前半段）
t ≥ 0：采样位置 = p + t × span × flow_fwd(p)   （曝光后半段）
```

在当前帧上做双线性插值采样，所有采样点等权平均，即为该像素的模糊结果。

**(3) 静止像素短路**
运动向量平方和 < 1e-4 的像素直接复制原值，避免平坦区域引入噪点闪烁。

**(4) 边界帧处理**
首帧/末帧缺少一侧邻居时复制当前帧作为邻居，该侧流为零，相当于快门减半，不会出错。

### 3.3 视频 I/O（`video.rs`）

- **探测**：`ffprobe` 以 `default=noprint_wrappers=1` 输出 `key=value` 逐行解析
  （**注意**：csv 模式不保证按 `-show_entries` 请求顺序返回字段，按列位置解析会错位——这是曾经导致进度条总数错误的根因）
- **帧率选择**：优先 `avg_frame_rate`（VFR 源的真实节奏），回退 `r_frame_rate`；输出时长与音轨保持同步
- **总帧数**：优先 `nb_frames`；缺失时按 `duration × avg_frame_rate` 估算
- **解码**：`ffmpeg -i INPUT -f rawvideo -pix_fmt rgb24 pipe:1`，按 `宽×高×3` 字节整块 `read_exact` 读帧
- **编码**：`ffmpeg -f rawvideo ... -i pipe:0 -i INPUT -map 0:v -map 1:a? -c:v libx264 ...`，音频流可选复制并转 AAC，`+faststart` 便于网络播放；双输入均设 `-thread_queue_size 512` 防队列阻塞

## 4. GPU 加速管线

GPU 路径（`--gpu`）将光流与模糊全部搬到 WGSL compute shader，**中间数据零回读**：

```
gray_cur/prev/next (CPU 灰度, rayon)
     │ 上传（每帧 3 次 H2D）
     ▼
高斯金字塔 ×3（gaussian_h/v + downsample_2x，单 encoder 单 submit）
     │ cur 金字塔被 fwd/bwd 两次求解共享
     ▼
LK 求解 ×2（gradients → products → box3 → iters × {warp_diff → box2 → solve_update}）
     │ 每个层级一次 submit；结构张量乘积由 products shader 在 GPU 完成
     ▼
中值滤波（median_3x3，结果留在显存）
     │
     ▼
motion_blur_px（打包 u32 RGB 沿轨迹采样）
     │
     ▼
回读最终 RGB（每帧唯一一次 D2H 同步）→ 编码线程
```

**14 个 compute shader**：gaussian_h / gaussian_v / downsample_2x / gradients / products / box3_h / box3_v / box2_h / box2_v / warp_diff / solve_update / median_3x3 / upscale_flow_2x / negate_flow / motion_blur_px。

**关键优化点**（相对朴素 GPU 移植）：

1. **消除中间回读**：朴素实现把梯度读回 CPU 算 ix²/iy²/ix·iy 再上传（每层级 2 次全量回读 + 3 次上传，每次回读都排空整条 GPU 队列）。`products` shader 使其全程在 GPU。
2. **批量提交**：同一阶段的所有 dispatch 录进一个 command encoder 一次 submit，消除每次 submit 的固定开销。
3. **金字塔复用**：当前帧的金字塔在 fwd/bwd 两次求解间共享，每帧少建一座。
4. **模糊上 GPU**：流场不再回读；每帧唯一的同步点是最终 RGB 图像回读（必需）。
5. **flow-cache 的取反也在 GPU**（`negate_flow` shader），缓存的是显存中的流场句柄（Arc）。
6. **灰度转换每帧一次**：灰度图随 RGB 帧一起轮转复用，避免同一帧转 3 次。
7. **帧缓冲池**：解码线程从池中取缓冲，退役缓冲由主循环归还，消除每帧 6 MB 的 clone。

**已修复的正确性缺陷**：

- 原 GPU 版 `warp_diff` 的两个输出绑定到同一缓冲，读回的 `It` 实为 `Iy·It`，时间梯度项一直是错的；
- `downsample_2x` 曾假设源宽 = 2×目标宽，奇数宽/高输入会行错位（现按真实源尺寸索引）。

## 5. 模块说明

| 文件 | 职责 | 关键公开接口 |
| --- | --- | --- |
| `src/main.rs` | CLI、三线程流水线、三帧滑动窗口、灰度缓存轮转、进度条 | `Args`（clap derive） |
| `src/video.rs` | ffprobe 探测（key=value 解析）、ffmpeg 解码/编码子进程管道 | `probe()` / `Decoder` / `Encoder` / `VideoInfo` |
| `src/flow.rs` | CPU：灰度图、高斯金字塔、LK 光流、中值滤波 | `Gray` / `FlowField` / `optical_flow()` / `median_flow()` |
| `src/blur.rs` | CPU：沿运动轨迹的定向模糊合成 | `motion_blur()` |
| `src/gpu.rs` | GPU：wgpu 上下文、14 个 compute shader、显存驻留的全帧管线 | `GpuContext` / `gpu_flows_device()` / `gpu_flow_single_device()` / `gpu_negate_flow()` / `gpu_motion_blur()` |
| `examples/synth.rs` | 合成移动方块的无依赖算法自验证 | 输出 PNG + 光流误差报告 |

**并行化**：CPU 路径所有行级循环使用 rayon `par_chunks_mut` 按行并行；前向/后向光流用 `rayon::join` 并发。GPU 路径以 16×16 workgroup 全像素并行。

## 6. 命令行参考

```
rsmb-rs <INPUT> -o <OUTPUT> [选项]
```

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `<INPUT>` | 路径 | 必填 | 输入视频（ffmpeg 支持的任意格式） |
| `-o, --output` | 路径 | 必填 | 输出视频路径 |
| `-s, --shutter` | 浮点 | 180 | 快门角度 0–360，控制模糊量；0 = 关闭模糊 |
| `--samples` | 整数 | 16 | 轨迹采样数；大运动建议 24–32 |
| `--window` | 整数 | 7 | LK 窗口半径；越大光流越平滑、细节越少 |
| `--iters` | 整数 | 5 | 每金字塔层迭代次数 |
| `--levels` | 整数 | 0 | 金字塔层数（0=自动 ≤6；越小越快、大位移越不准） |
| `--flow-cache` | 开关 | 关 | 复用前向流取反作后向流，约省一半光流计算 |
| `--gpu` | 开关 | 关 | GPU 加速（wgpu，需 Vulkan/DX12/Metal 驱动） |
| `--crf` | 0–51 | 18 | x264 质量（越小越好） |
| `--preset` | 字符串 | medium | x264 预设（veryfast/medium/slow…） |
| `--ffmpeg` | 路径 | ffmpeg | ffmpeg 可执行文件路径（ffprobe 自动取同目录） |

**典型用法**

```bash
# 标准电影感模糊（GPU）
rsmb-rs input.mp4 -o out.mp4 --gpu

# 强模糊 + 高质量
rsmb-rs input.mp4 -o out.mp4 --gpu --shutter 300 --samples 32 --crf 16 --preset slow

# 快速预览
rsmb-rs input.mp4 -o preview.mp4 --gpu --levels 2 --flow-cache --samples 8 --preset veryfast

# 指定 ffmpeg 位置
rsmb-rs input.mp4 -o out.mp4 --ffmpeg "C:\ffmpeg\bin\ffmpeg.exe"
```

## 7. 构建与运行

**前置条件**

- Rust 工具链（≥ 1.75，`rustup` 安装）
- ffmpeg 与 ffprobe（PATH 中，或用 `--ffmpeg` 指定）
- GPU 模式：支持 Vulkan / DX12 / Metal 的显卡及驱动

**构建**

```bash
cargo build --release        # 产物：target/release/rsmb-rs.exe
```

**算法自验证（无需 ffmpeg、无需 GPU）**

```bash
cargo run --release --example synth
# 输出光流误差报告 + synth_original.png / synth_blurred.png
```

## 8. 性能指标与实测数据

**实测环境**：Windows 11，rustc 1.96.1，release 构建（LTO + codegen-units=1），GPU 为 Intel UHD 750 核显。

测试素材：1920×1080 @ 60fps 游戏录屏，3 秒（180 帧），shutter=180°、samples=16、window=7、iters=5、preset=veryfast。

| 配置 | 耗时 | 吞吐 | 相对加速 |
| --- | --- | --- | --- |
| 纯 CPU | 3m49s | 0.79 fps | 1× |
| GPU 初版（含 CPU 回读） | 1m49s | 1.65 fps | 2.1× |
| GPU 优化版（全程显存驻留 + GPU 模糊） | **1m05s** | **2.79 fps** | **3.5×**（对 GPU 初版 1.7×） |

- 端到端正确性：输出 180 帧与输入一致；抽帧对比运动区域拖影方向与 CPU 版一致
- 内存/显存：CPU 侧恒定（3 帧 RGB + 灰度 + 流场）；GPU 侧每帧约数十个临时缓冲，帧结束即释放
- 注意：测试 GPU 为核显，独显上加速比显著更高

**性能调优建议**

- 优先 `--gpu`；`--levels 3 --flow-cache` 再提速 50-80%
- 大位移场景优先增大 `--samples` 避免拖影断层
- 预览时 `--samples 8` + `--preset ultrafast`
- 光流计算量与分辨率成正比：1080p → 720p 约提速 2.2 倍

## 9. 已知限制与改进方向

| 限制 | 说明 | 可能的改进 |
| --- | --- | --- |
| 遮挡区域伪影 | 单帧轨迹采样，物体边缘遮挡/显露处可能轻微拉丝 | 引入前后帧可见性（occlusion）权重，多帧采样 |
| 平坦纹理区光流噪声 | LK 孔径问题 | 增大 `--window`，或换用 Farnebäck / 深度学习光流（RAFT） |
| 超大位移 | 金字塔层数上限 6 | 提高层数上限或加稀疏匹配初始化 |
| 模糊仅采样当前帧 | 快速近似，非物理精确积分 | 混合前后帧样本的三角形曝光积分 |
| 编码器固定 libx264 | 未暴露硬件编码选项 | 增加 `--encoder hevc_nvenc` 等参数 |
| GPU/CPU 每帧仍有 1 次同步 | 最终 RGB 必须回读给编码器 | 双缓冲重叠：帧 N 提交 GPU 后立刻处理帧 N+1 的灰度与金字塔 |

## 10. 故障排查

| 现象 | 原因与解决 |
| --- | --- |
| `failed to run ffprobe` | ffmpeg 未安装或不在 PATH；用 `--ffmpeg` 指定完整路径 |
| `encoder pipe closed unexpectedly` | 输出目录不存在或 x264 参数不被支持；检查 ffmpeg stderr |
| 进度条总数明显偏大 | 旧版本 ffprobe 字段解析 bug（csv 列序不保证），请升级到按 key=value 解析的版本 |
| 输出帧数少于输入（WARNING 提示） | 解码器中途失败（间歇性）；重跑一般可恢复，已加 `-thread_queue_size 512` 加固 |
| 输出画面整体发糊 | `--shutter` 过大或 `--window` 过大；降到 180/7 起步 |
| 拖影呈颗粒状断裂 | 运动幅度大但采样不足；增大 `--samples` |
| GPU 模式报 `no suitable GPU adapter` | 显卡驱动过旧或不支持 Vulkan/DX12；更新驱动或去掉 `--gpu` 用 CPU 路径 |
| 处理速度慢 | 见第 8 节调优建议 |
